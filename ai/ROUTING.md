The table is a map, not a gate: an unlisted model is routable when it is the structurally right tool (rule 1c), you name why, and its id verifiably works. Prefer a listed tier.

External dispatch (Codex and Grok): write the full prompt to a temp file. Codex: `codex exec --dangerously-bypass-approvals-and-sandbox -m <model> [-c model_reasoning_effort="<level>"] < <file>`. Only the three `gpt-5.6-*` ids above work (bare `gpt-5.6` and `-codex` ids 400 on a ChatGPT account). Grok: `grok --prompt-file <file> --always-approve` (add `-m <id>` only for a model `grok models` lists; file form because grok's argv parser word-splits spaced prompts under Windows shells). A grok "You are not authenticated" reply means the token lapsed: ask the user to run `! grok login --device-auth`, do not retry. Both run standalone with no shared context; read the final assistant message from stdout and judge it yourself before treating it as a completion claim.

Before the decision order: does this need a model at all? A grep, sed sweep, script, SQL query, formatter, linter, type checker, or `git log` is free, deterministic, and cannot hallucinate. Spend a model only on judgment, and push the mechanical part into a command the model runs, not tokens it generates.

Decision order for any delegated task:
0. Local PC control (OS settings, services, processes, scheduled tasks, installs, power, devices, desktop automation): Codex on `gpt-5.6-terra`, the only external path for it. Verify the change took effect before claiming completion. Destructive or hard-to-reverse system changes need user confirmation first; this rule changes who executes, not what needs approval.
1. Codex first: the plan is flat-rate and already paid, so exhaust it before metered Claude usage. Pick the tier by slice difficulty: `luna` for trivial mechanical work (formulaic single-file edits, renames, lookups, scripted sweeps), `terra` for an ordinary coding slice (the default when unsure), `sol` at `high`+ effort for debugging, cross-cutting refactors, architecture-shaped implementation, and second opinions on large or risky diffs. Keep off Codex only work needing Claude-side tools (MCP, subagents, session context, live back-and-forth), security-sensitive code, final review of large/risky diffs, and judgment gating a completion claim; those stay on Claude regardless of quota. Judge Codex output yourself before accepting it.
1a. Codex quota exhausted (rate-limit or usage-cap error): step DOWN one Codex tier (`sol` to `terra` to `luna`, each has its own pool); only when `luna` also refuses, fall back to the Claude tier per rule 2 for the session and tell the user the cap was hit; retry Codex later.
1b. Grok by default for: research or current-events/real-time/X lookups; an independent non-OpenAI, non-Anthropic opinion (consensus tie-breaker, or third check when Codex and Claude agree); a second external executor on self-contained slices when Codex is saturated.
1c. Structural fit outranks quota and price: when exactly one model can do the job at all (Grok for live web and X, a long-context model for a sweep no other window holds, a multimodal model for video or images), route there directly and skip rules 1 and 2. No listed model fits: say so and propose the tool, do not fake it with a model that cannot see the input.
2. Work kept off Codex by rule 1, or after a 1a fallback: `opus` is the default Claude coding tier, including implementation, multi-file changes, debugging, review, and any task of uncertain complexity. Drop to `sonnet` only for one-shot slices with simple, checkable output (formulaic single-file edits, simple lookups, routine read-only sweeps) where opus changes nothing; anything open-ended, multi-step, or uncertain goes `opus`, because a task costs price times turns-to-done, and a cheaper tier that fails once lands above a pricier one that one-shots it. `haiku` sits one floor below: only one-shot jobs whose whole output is a short answer checkable at a glance (classify, label, extract a field, fixed-format lookup, mechanical text transform), never code edits, debugging, review, a judgment gating a completion claim, or a stand-in for a merely small slice.
3. A task failing concretely on a lower tier reruns one tier up (`luna` to `terra`, `terra` to `sol`, `haiku` to `sonnet`, `sonnet` to `opus`), never another pass on the same tier. Never downroute below these floors to "balance" a spread.
4. Agent type: read-only searches and codebase sweeps use `Explore`, not `general-purpose`. Every spawn of every type pins `model` explicitly: `opus`, `fable` where a slice is pinned to it, or `sonnet` or `haiku` when rule 2 puts the slice on that floor. Omitting `model` inherits the session model, making the tier an accident, not a choice; `hooks/enforce-spawn-model.mjs` denies it.
5. Change a default only on `evals/` evidence (same tasks, competing routes, judged output), never on a hunch. No eval covers the slice: write the task first, then reroute.

Delegation prompt quality (every Agent spawn, every Codex or Grok dispatch): the target cannot see this conversation, so each prompt carries objective + definition of done, unseen context (paths, prior decisions, constraints, the "why"), an output contract that fits back into context (summary, not raw dump), tool/source guidance, and boundaries (scope limits, don't-touch zones, when to stop and report instead of guessing). Every Agent spawn prompt includes literal `Scope:`, `Out of scope:`, and `Definition of done:` lines; `hooks/enforce-spawn-model.mjs` denies one without them. Not handable to a competent stranger: not ready to send. Never restate AGENTS.md standing rules; they already reach every tool (Claude subagents inherit it, Codex reads `~/.codex/AGENTS.md` plus repo AGENTS.md, Grok reads repo AGENTS.md).

Orchestration posture by active session model:
- Opus: organize the work yourself, deploy agents to execute it. Decompose into well-bounded slices, dispatch independent ones concurrently, scale the fleet to complexity (1 for a lookup, 2-4 for a comparison, a fleet plus synthesis pass for a broad audit). Planning, synthesis, and final verification stay in the main loop; never rubber-stamp agent output. No agent for a one-line edit, a single command, or work needing live back-and-forth.
- Fable: aggressive orchestrator, never worker. Main-loop tool calls are a scarce budget: anything expected to exceed ~3 tool calls, touch more than one file, or produce output the user will not read verbatim gets dispatched per the decision order, not done inline. Dispatch independent slices concurrently and keep working while they run, intervening when one drifts; when torn between doing and delegating, delegate. Main loop keeps only decomposition, judging results, and composing the final response. Direct work only for single-command ops, trivial one-file edits, and answers already in conversation context.
- Any other session model: apply the decision order directly, no special posture.
