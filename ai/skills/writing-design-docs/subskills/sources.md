# Sources

Gather everything the doc will claim before writing a line of it.

- **Read the doc's history.** Find every earlier version, plan, and artifact on the topic and read them in full. The bigger picture (what was planned, built, dropped, and why) lives there, and a restructure that skips it ships an MVP doc with no roadmap. Record each earlier decision with its reason so the doc can say why a path was dropped.
- **Read the code the doc describes.** Note the file and line for every behavior the doc will state. A setting the doc says exists, or a step it says can be skipped, must be found in the code.
- **Pull the real numbers.** Volume, rates, durations, and prices come from production data, run logs, or the provider's price page, each with its date range. Write down what each number excludes and why.
- **Collect the author's own material.** Their notes, Slack threads, and feedback they pasted are the questions the doc must answer. A reviewer's question quoted in the chat becomes a section or a row, not a footnote.
- **Keep raw pulls in the scratchpad**, not the doc: query output, run lists, and sweeps go in files the appendix can cite.
