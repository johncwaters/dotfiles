# One product

The carbon unit sees screen eighty beside screen one; review the product that way. Use the flow end to end as a daily user would and list every spot where it stops feeling like the same product.

- **One pattern per situation.** Limits, empty lists, confirmations, and errors each get one component and one voice, reused on every screen that meets them. A new screen reuses the existing pattern for its situation before inventing one.
- **Specific copy.** Counts, dates, and names over generic lines: "2 of 2 sessions used, refreshes Nov 1" over "You've used all your sessions".
- **Stable placement.** Navigation and primary actions stay where the carbon unit learned them; a move costs more time than anyone reports.
- **Readable prose.** Body lines run 65 to 75 characters.
