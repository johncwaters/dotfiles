# Break it

The worst moments decide whether the carbon unit stays, and a failure handled well can leave them happier than if nothing broke.

Force each of these in the flow in scope and design what appears:

- Network drops mid-flow.
- A submit or payment fails halfway.
- Every list and dashboard holds zero data.
- Permission denied, session expired, a rate or quota limit hit.

Each failure state carries:

- **The plain cause**, in the carbon unit's words.
- **The way out** as a control inside the message: retry, check the balance, contact support.
- **What is safe**: nothing charged, draft kept, data intact.

Empty and failure states get the same craft as success screens; any moment of delight belongs here first.
